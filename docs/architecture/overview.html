L2 Container

One Go process, a config file you write and one SQLite file it writes: 100 chats and 5,000 messages a day need no broker

ContainerWhat it isTechnology
tgscoutone process: reads Telegram, asks the LLM, sends found messages, writes the consoleGo, CLI
tgscout.yamlconfig you write: requests, each with its chats; catch-up depth (messages, days); LM Studio address and modelYAML file
storeprocessed IDs, last ID per chat, match decisions (the «yes» ones are the found messages)SQLite, one local file

Config

Settings are hierarchical: set them once at the root, override them for one request, override them again for one chat of that request. The nearest level wins: chat, then request, then root.

owner: "@your_username"   # tgscout writes to you here
workers: 2
lm_studio:
  url: http://localhost:1234/v1
  model: <model name>
  timeout: 60s
catch_up:                 # root: for every request and chat
  messages: 500
  days: 3
requests:
  - id: lego-duplo-train
    find: |
      LEGO Duplo with a train and a railway, up to 60 €
    catch_up: {days: 7}        # this request only
    chats:
      - "@kids_market"
      - ref: "https://t.me/lego_sale"
        catch_up: {messages: 2000}   # this chat of this request only
  - id: kids-bike
    find: A kids' bike, 16 inch, under 100 €
    chats: ["@kids_market"]

Secrets are never in this file: the Telegram api_id, api_hash and the session live in .env and the session file.
