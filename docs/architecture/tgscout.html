tgscout.yaml

Proposal: settings are read root, then request, then chat; a request or a chat may override the catch-up depth

Agreed so far

  • At peak, messages wait in an in-memory queue (a Go channel) before the matcher.
  • The cursor is the last processed message ID of each chat, kept in SQLite.
  • After a restart, catch-up rereads from Telegram from the cursor and skips IDs already in SQLite: nothing is lost.
